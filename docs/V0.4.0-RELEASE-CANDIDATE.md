## Independent reproducibility gate

`.github/workflows/ci.yml` builds the unsigned Gradle APK with Temurin 25,
then runs `tools/qa_fdroid_rebuild.sh` as part of the normal CI gate to:

1. Copy the exact checkout commit into a disposable F-Droid source clone.
2. Create temporary, **disabled** metadata for v0.4.0 versionCode 10
   requesting Debian Trixie OpenJDK 25.
3. Run a fresh F-Droid `build --test --force` in the Trixie CI
   container, with no signing secrets.
4. Compare the **complete unsigned APK byte-for-byte** against the
   runner APK and **fail closed** if they differ.

The matching SHA-256 check is a prerequisite for producing an official-key
signed candidate, but does not prove acceptance by F-Droid's actual
production buildserver VM. No metadata is submitted.

## How an authorized reviewer obtains the signed RC

Prerequisite: merge the tested v0.4.0 code into `main`.

`.github/workflows/release-candidate.yml` runs only on the
exact branch `rc/v0.4.0` (or a manual dispatch selecting that branch).
Creating this branch at the reviewed main commit runs the QA-only workflow.
It does **not** invoke the publishing workflow, whose triggers are
exclusively `v*` tags or `publish/v*` branch pushes.

The candidate workflow:
1. Rechecks versionName/code, minSdk, applicationId, disabled v0.3.0 recipe.
2. Runs lint, unit tests and a Java 25 unsigned release build.
3. Rebuilds independently in F-Droid Trixie; requires byte-identical APK.
4. Only after passing, restores the **existing production keystore** from
   GitHub Actions secrets (never checks it into git or passes it to Docker).
5. Signs with Android Build Tools **34.0.0**, verifies the **same**
   production certificate and `apksigcopier compare --unsigned`.
6. Verifies package/version, minSdk, API 25 signature validation.
7. Uploads `lyrion-display-v0.4.0-rc.apk` and SHA-256 as a
   short-lived GitHub Actions artifact, **not** as a GitHub Release.

The artifact is available for QA; retention is 14 days.
Never use a debug-signed APK to test an in-place upgrade over v0.3.0.

## Real Fire TV QA before any public release

From Windows PowerShell, with Android SDK Platform Tools installed:

```powershell
adb connect FIRE_TV_IP:5555
adb shell getprop ro.product.model
adb shell getprop ro.build.version.sdk
# Expect AFTMM and 25
adb install -r "lyrion-display-v0.4.0-rc.apk"
adb shell am force-stop com.chrober.lmsmaterial.nowplaying
adb logcat -c
adb shell am start -W -n com.chrober.lmsmaterial.nowplaying/.MainActivity
# Once the Now Playing display is visible:
adb logcat -d -s LyrionStartup:I
```

Before installing, **keep the existing v0.3.0 installed**, and take note
of configured server, player, theme and Now Playing options.

Acceptance:
- Upgrade installs with `adb install -r` without uninstalling, changing
  package ID, losing preferences or changing signing certificate.
- Launcher icon and full-screen display work on Fire OS 6.
- Menu, D-pad, OK, Back and Settings work with Alexa Voice Remote.
- Cover art, track changes, queue display stay view-only.
- Cold-start timings captured on 5–10 runs (baseline, not proven improvement).
- Return from Settings reuses the verified WebView.
- Unavailable server displays native error, never an unverified page.
- Several hours of running Now Playing without renderer crashes.
- Screen awake setting works as in v0.3.0.
