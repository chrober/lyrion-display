# v0.4.0 — opt-in early Now Playing readiness A/B experiment

**QA only, unpublished, OFF by default.** Supports API 23+ (including the
original Fire TV Stick 4K / Fire OS 6 / API 25); minSdk 22 unchanged.

## Motivation from real hardware

Five cold starts: total startup median **3475 ms**, final page load
**2034 ms**, options callback **598 ms**, but actual options script
execution only **0.7 ms**. WebView commit sometimes arrives after
onPageFinished; simply using commit as readiness would be unsafe.

## How the experiment works

Settings → PERFORMANCE (EXPERIMENTAL) → **Early Now Playing readiness**.

- Existing trusted origin/server probe stays mandatory before navigation.
- On API23+ final-page commit, issue a bounded, read-only DOM check.
- Require two consecutive checks with the #app root, visible laid-out
  Now Playing controls and an ancestor Vue instance mounted.
- At most eight checks, 160 ms between attempts; no JS bridge and no
  new network requests, metadata reads, or player controls.
- Only after passing those checks run the existing display-options
  JavaScript and postVisualStateCallback, with the native overlay held
  until the existing completion callback.
- The original onPageFinished readiness path remains the fallback.
  If a speculative early options evaluation hangs, a 1.4-second
  watchdog resumes the normal path; stale evaluations are ignored.
- Disabling the checkbox restores the original behavior on next
  navigation/cold connection. API22 cannot enable this experiment.

Important: visible Vue controls do not guarantee album art or track
metadata finished loading. Check actual Fire TV output for blank content,
flicker, wrong player, new delays, and unexpected WebView crashes.

## Logcat

The existing LyrionStartup line retains total_ms and visual_state.
The native LyrionStartupDetail line adds:

- early_mode=off|on: selected experiment state
- early_probes: number of passive checks attempted
- early_candidate_ms: elapsed from navigation to stable visible controls
  (-1 when not reached)
- ready_source=early|finished|none: whether the original JavaScript
  readiness completed before onPageFinished (or used its fallback)

Use the same PowerShell test block as the earlier navigation profiling
document. Keep Pre-render hidden WebView OFF. Run OFF → ON → OFF → ON,
at least five cold launches per block; compare median total_ms and
successful callback/timeout rates. **Do not interpret ready_source=early**
as proof of complete track/player contents or an actual speedup.

Useful success criterion: at least **200–300 ms reproducible median
improvement**, with no incomplete Now Playing UI or stability regressions.
This threshold is a test objective, not an expected result.

Do not publish v0.4.0, tag a release or submit F-Droid until hardware
acceptance. The signed candidate must be built with the existing production
certificate, reproducible and pass API22/25/29 Android instrumentation.
